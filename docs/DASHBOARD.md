# Symphony 管理控制台

控制台参考用户提供的 [Symphony 演示视频](https://player.vimeo.com/video/1186371009?h=5626e4b899) 中的浅色任务看板与详情布局，使用本地静态资源，无 CDN 或额外前端依赖。

## 启动

在项目根目录运行：

```powershell
npm.cmd run build
node dist/src/cli.js examples/WORKFLOW.space-tetris.md
```

该工作流使用 `.env` 的 GitHub 凭据，控制台地址为 `http://127.0.0.1:8081`。它是完整调度服务，带 `symphony:e2e` 标签的符合条件任务会被自动执行；`symphony:review` 的任务不会重复派发。不要同时启动两个相同工作流实例。

不接入 GitHub 时可运行 `npm.cmd start`，默认本地文件任务源的控制台位于 `http://127.0.0.1:8080`。Ctrl+C 停止服务。端口跟随工作流 `server.port` 或命令行 `--port`。

## 页面功能

- 看板和列表，按标题、编号或标签搜索；`/` 快捷键聚焦搜索。
- 配置多个 GitHub 仓库后，可按仓库筛选看板/列表；顶部指标和活动页仍为所有仓库汇总，详情显示所属仓库。
- 六种状态：待安排、待调度、进行中、等待重试、待审查、需处理。待安排表示尚未满足调度标签或负责人等条件。
- 任务详情显示原始描述、任务源状态、标签；运行任务另显示会话、轮次、Token 和最近事件，重试任务另显示次数、时间和错误。
- 运行指标显示当前 Agent 数、并发上限、等待重试数、待审查数、当前服务会话的累计 Token 和运行时间。
- 活动页显示本次服务会话最近 100 条任务事件，出现 PR 交接事件时提供 PR 链接。
- 服务页只显示白名单配置，不返回令牌、完整 provider 配置或 `.env`。
- 页面每 5 秒读取状态，任务源按工作流自身间隔同步。手动刷新调用既有调度刷新接口，排队成功不代表任务源读取已完成。
- 网络错误时保留旧数据并标记过期，后续请求成功自动恢复。

## 数据边界

控制台展示调度器最近观察到的 active 状态任务，GitHub 的待审查与阻塞任务通过标签归类。它不是所有历史 Issue 的归档；已关闭任务可能离开快照。Token、活动和时间统计不跨进程重启持久化。

任务详情中的“保留进度并重试”支持已启用自动发布的 GitHub 仓库：补齐工作流要求的调度标签、移除该仓库的阻塞标签、清除重试等待并立即请求调度。工作区、分支和提交保留；仍受全局并发限制。按钮请求成功表示已排队，不代表开发或发布完成。权限或网络错误会显示在详情中。

运行中、已关闭、待审查、负责人不匹配或已有 PR（含关闭/合并）的任务会被拒绝，避免重复开发及破坏已交接的工作。当前不支持强制终止运行任务或在已有 PR 上继续开发。修复失败原因后再重试，否则可能再次阻塞。

接口为 `POST /api/v1/issues/<encodeURIComponent(issue.id)>/restart`，例如 ID 为 `owner/repo#3`。仅允许本机 Host 和同源浏览器请求，后台按已配置仓库及其凭据处理，前端不接触令牌。任务创建、其他编辑和 PR 审查仍在任务源进行。
